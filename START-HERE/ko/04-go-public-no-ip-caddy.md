# 04. 정원을 인터넷에 올리기(웹 이름, HTTPS, 로그인 페이지)

> 영어 원문: [../04-go-public-no-ip-caddy.md](../04-go-public-no-ip-caddy.md)

## 짧은 버전
*다 읽을 시간이 없나요? 짧은 버전이에요. 전체 안내서는 아래에 있어요.*

- 이 안내서는 정원을 인터넷의 `https://junsgarden.zapto.org`에 올려요. 자물쇠와 로그인 페이지도 있어요. 거의 모든 일은 메뉴가 해요: 메뉴 `M`, 그다음 `1`.
- 약 1시간 걸려요. 무료예요.
- 따로 있는 정원 컴퓨터(Ubuntu 노트북 또는 Pi)가 필요해요. Windows 안의 Ubuntu(WSL)에 있는 정원은 그 PC에서만 쓰는 용도예요("정문 단계의 세 가지 선택" 아래의 안내를 보세요).
- A 부분: 내 무료 No-IP 계정을 만들고, 이름을 만들고, DDNS 키를 만드세요.
- B 부분: CGNAT(여러 집이 주소 하나를 나눠 씀) 뒤에 있지 않은지 확인하세요. CGNAT라면 집에서 사이트를 운영할 수 없어요: 인터넷 회사에 공인 IP 주소(public IP address)를 요청하세요.
- C 부분: 먼저 선택 `2`와 지어낸 `.test` 이름으로 연습하세요.
- D 부분: 진짜 이름은 선택 `3`. 그다음 공유기에서 포트 80과 443을 전달하세요(안내서 14). Wi-Fi를 끈 휴대폰으로 테스트하세요.
- 주의: 포트 80과 443만 전달하세요. 22, 8030, 3306, 8123이나 다른 포트는 절대 안 돼요.
- 무료 No-IP 이름은 30일마다 확인해야 해요: No-IP 이메일에서 **Confirm**을 누르지 않으면 이름이 작동을 멈춰요.

## 무엇을 만드나요
**https://junsgarden.zapto.org**에 있는 내 정원. 자물쇠가 있고, 예전과 같은 관문이 있고
(정원 도구는 로그인한 뒤에만 열려요), 공유기(router)에는 포트가 두 개만 열려 있어요.
거의 모든 일은 메뉴가 해요: 메뉴 `M`, 그다음 `1`(**The front door**, 정문). 이 안내서는
각 부분과, 본인만 할 수 있는 몇 가지를 설명해요.

| 부분 | 하는 일 | 공식 페이지 |
|---|---|---|
| **No-IP + 업데이트 프로그램(DUC)** | 인터넷 회사가 집의 인터넷 주소를 바꿔도, 웹 이름이 계속 집을 가리키게 해요 | <https://www.noip.com/support/knowledgebase/> |
| **Caddy** | 정문이에요. 포트 80과 443에서 방문자를 받고, HTTPS 자물쇠를 스스로 받아 오고, 각 방문을 알맞은 프로그램에 넘겨줘요 | <https://caddyserver.com/docs/> |
| **Authelia** | `/auth`에 있는 내 로그인 페이지. 정원 도구 앞에 있어요 | <https://www.authelia.com> |
| **내 공유기** | 정원 컴퓨터의 주소를 예약하고, 포트 80과 443을 그 컴퓨터로 전달해요. 그 밖에는 아무것도 하지 않아요 | 안내서 [14](14-reserve-your-ip.md) |

## 시간과 비용
약 1시간. 무료예요. 무료 No-IP 이름은 30일마다 확인해야 해요: No-IP가 이메일로 링크를
보내 주면 **Confirm**(확인)을 누르세요.

## 먼저 읽으세요
> **이것은 우리 집을 인터넷에 여는 일이에요.** 몇 시간 안에 로봇들이 문을 두드려요.
> 정상이에요. 그래서 설정을 조심스럽게 해요:
> - 포트 **80**과 **443**만 정원 컴퓨터로 가요. 22(SSH), 8030, 3306, 8123(Home Assistant)
>   이나 다른 포트는 절대 전달하지 마세요.
> - Caddy 말고는 모두 정원 컴퓨터 자신에서만 들어요.
> - Ubuntu를 계속 업데이트하세요. 점검표(메뉴 `5`)가 업데이트가 기다리고 있으면 알려 줘요.
> - 인터넷 회사가 여러 집을 주소 하나 뒤에 묶어 두면("CGNAT"), 집에서 사이트를 운영할 수
>   없어요. B 부분에서 확인하는 방법을 보여 줘요.

## 정문 단계의 세 가지 선택(메뉴 `M`, 그다음 `1`)

![보게 될 화면: 정문의 세 가지 선택](../images/screen-14-front-door.png)

| 선택 | 얻는 것 | 필요한 것 |
|---|---|---|
| **1 아직 인터넷에 없음**(집 Wi-Fi에서만, www 없음) | 집 Wi-Fi에 있는 휴대폰과 컴퓨터가 `http://노트북이름.local`(그리고 노트북의 IP 주소)에서 정원을 봐요. 집 밖에서는 아무도 들어올 수 없고, 공유기는 건드리지 않아요. 정원 도구는 선택 3 전까지 비공개예요. | 없음. 지금 쓰세요. **다음 단계:** No-IP에 가입하고(A 부분), 하위 이름을 원하면 DuckDNS(선택, 고급 참고), 그다음 선택 3. |
| **2 연습** | 모든 것(HTTPS, 로그인 페이지, 관문)이 지어낸 `.test` 이름으로 노트북 안에서만 작동해요. | 없음. 배우기에 좋아요. |
| **3 진짜 웹 이름** | 모든 사람을 위한 `https://junsgarden.zapto.org`, 자물쇠와 로그인 페이지 포함. | 내 No-IP 계정과 이름(A 부분), 그리고 공유기(안내서 14). |

> **Windows PC 안의 Ubuntu(WSL)에서 정원을 돌리고 있나요?** 그러면 선택 1(집 Wi-Fi에서만)과
> 선택 3(인터넷)은 여기 적힌 대로 작동하지 않아요. Windows 안의 Ubuntu는 PC 안에 자기만의
> 내부 주소가 있어서, 공유기와 휴대폰이 거기에 닿을 수 없어요. 그 Windows PC에서 정원은
> PC 자신에서 쓰는 용도예요. 정원을 인터넷에 올리거나, 집에 있는 다른 휴대폰과 컴퓨터에
> 보여 주려면, 따로 있는 정원 컴퓨터를 쓰세요: Ubuntu 노트북(안내서 01) 또는 Raspberry Pi.
> WSL의 네트워크가 어떻게 작동하는지 더 알고 싶나요? Microsoft가 여기서 설명해요(읽기만
> 하세요. 정원은 이것을 설정하지 않아요): <https://learn.microsoft.com/windows/wsl/networking>

## A 부분. 내 No-IP 계정과 이름(한 번만)
1. <https://www.noip.com>에서 무료 계정을 만드세요(본인의 이메일을 쓰세요). No-IP가 보낸 이메일로 확인하세요.
   무료 요금제는 웹 이름이 **하나**이고, 30일마다 확인해야 해요(No-IP가 링크를 이메일로 보내요. 확인하지 않은
   이름은 삭제돼요). 유료 Enhanced 요금제는 3개예요(<https://www.noip.com/remote-access>).
   하나면 충분해요: 주소가 더 필요하면 DuckDNS로 무료로 만들 수 있어요(아래 고급 참고).
2. **Dynamic DNS, No-IP Hostnames, Create Hostname.** Name(이름): `junsgarden`,
   domain(도메인): `zapto.org`. (이름이 이미 쓰이고 있다고 하면, 하루 기다렸다가 다시 하거나
   다른 이름을 고르세요. 메뉴는 어떤 이름이든 작동해요.)
3. **Dynamic DNS, DDNS Keys, Add DDNS Key.** 내 호스트 이름(hostname)을 고르세요. 키의
   **username**(사용자 이름)과 **password**(비밀번호)를 안전한 곳(비밀번호 관리자)에 적어 두세요.
   DDNS 키는 내 이름만 업데이트할 수 있어요. 내 계정에 로그인할 수는 없어서,
   컴퓨터에 두기에 안전해요.

## B 부분. CGNAT 뒤에 있지 않은지 확인하기
공유기 페이지에서 **WAN** 또는 **Internet** 주소를 찾으세요. 정원 컴퓨터에서
`curl -s https://api.ipify.org; echo`를 실행하세요. 두 주소가 같으면 괜찮아요. 공유기가
`10.`, `100.64.`~`100.127.`, 또는 `192.168.`로 시작하는 주소를 보여 주면, 인터넷 회사가
여러 집에 주소 하나를 나눠 쓰고 있는 거예요. 인터넷 회사에 "public IP address"(공인 IP 주소)를
요청하거나(무료인 경우도 있어요), 정원을 집 안에서만 쓰세요.

## C 부분. 먼저 연습하기(추천)
이것은 정원 컴퓨터 자신의 화면과 키보드 앞에서 하세요(Windows PC 안의 Ubuntu로는 할 수
없어요). 메뉴 `M`, `1`, 그다음 선택 `2`. 웹 이름에는 `.test`로 끝나는 지어낸 이름을 입력하세요. 예:
`garden.test`. 모든 것(Caddy, 로그인 페이지, 관문)이 연습용 인증서로 정원 컴퓨터에만
설정돼요. 인터넷에서는 아무것도 바뀌지 않아요. 그 컴퓨터의 Firefox에서 `https://garden.test`를
여세요. Firefox가 연습용 인증서라고 경고해요: 예상한 일이에요. **Advanced…**(고급…)를 누르고,
그다음 **Accept the Risk and Continue**(위험을 감수하고 계속)를 누르세요. `/beds`도 열어 보고
로그인해 보세요. 마음에 들면 D 부분을 하세요.

## D 부분. 진짜로 하기
1. 공유기에서 정원 컴퓨터의 주소를 예약하세요(안내서 [14](14-reserve-your-ip.md), 1단계와 2단계).
2. 메뉴 `M`, `1`, 그다음 선택 `3`. 웹 이름: `junsgarden.zapto.org`(또는 내가 고른 웹 이름). 이 이름이 내 No-IP 계정에 있는지 물으면 `y`를 입력하세요.
   Caddy를 설치하고, 로그인 페이지를 시작하고, 방화벽에서 포트 80과 443을 열고,
   No-IP 업데이트 프로그램을 설치하고(A 부분의 DDNS 키를 입력하세요. 비밀번호는 보이지
   않아요), 비밀번호를 정하라고 해요.
3. 공유기에서 TCP **80**과 **443**을 정원 컴퓨터의 주소로 전달하세요(안내서
   [14](14-reserve-your-ip.md), 3단계). 그 밖에는 아무것도 하지 마세요.
4. **Wi-Fi를 끈** 휴대폰으로 테스트하세요: `https://junsgarden.zapto.org`를 여세요.
   처음 방문은 Caddy가 인증서를 받는 동안 30초쯤 걸릴 수 있어요.
5. 점검표(메뉴 `5`)를 실행하세요. 6번 부분이 이름이 우리 집을 가리키는지 확인해요.

## 정문 단계가 컴퓨터에서 바꾸는 것
- 공식 출처에서 Caddy를 설치하고, `docker/caddy/Caddyfile.template`으로
  `/etc/caddy/Caddyfile`을 써요. 읽어 보세요: `cat /etc/caddy/Caddyfile`.
- 로그인 페이지의 설정을 `local/authelia/`에 써요(비공개, 본인만 읽을 수 있어요).
- 방화벽: 80과 443을 허용해요.
- No-IP 업데이트 프로그램을 설치하고 키를 `/etc/default/noip-duc`에 저장해요(관리자만 읽을 수 있어요).
- 비밀번호 이메일이 진짜 주소로 연결되도록 `PUBLIC_URL`을 정해요.

## 고급(선택): DuckDNS로 하위 도메인 만들기

![하위 도메인 메뉴(메뉴 M, 그다음 13)](../images/screen-15-subdomains.png)

**왜:** `junsgarden.zapto.org` 같은 무료 No-IP 이름은 하위 이름(subdomain)을 가질 수 없어요
(`wiki.junsgarden.zapto.org`는 없어요). 무료 **DuckDNS** 이름은 가질 수 있어요:
`wiki.junsgarden.duckdns.org`, `n8n.junsgarden.duckdns.org`, `status.junsgarden.duckdns.org`
모두 우리 집을 가리켜요(DuckDNS: <https://www.duckdns.org/spec.jsp>). 일마다 주소를 따로 두면 좋아요.
예를 들어 Home Assistant 패널이나 자동화를 각자 내 로그인 페이지 뒤에 두면, 프로그램마다 인터넷에 따로 여는 것보다
훨씬 적게 드러나요. 그러면 추가 프로그램마다 깔끔한 자기 주소와 자기 자물쇠가 생기고,
공유기 포트는 똑같이 두 개만 써요. 정원은 `junsgarden.zapto.org`에 그대로 있어요.

**방법(메뉴 `M`, 그다음 `13`, Subdomains(하위 도메인)):**
1. `1`을 고르세요: <https://www.duckdns.org>에서 로그인하고(Google 또는 GitHub 로그인),
   이름을 추가하고(예: `junsgarden`, 비어 있다면), **token**(토큰)을 복사해서
   붙여 넣으세요(보이지 않아요). 메뉴가 DuckDNS에서 확인하고, 토큰을
   `~/.config/garden-duckdns/token`에 저장하고(본인만 읽을 수 있어요), 5분마다 도는
   업데이트 프로그램을 추가해요(cron 한 줄, DuckDNS의 설치 페이지가 보여 주는 방법 그대로:
   <https://www.duckdns.org/install.jsp>).
2. `2`를 고르면 하위 도메인을 추가해요: `wiki`(내 위키), `n8n`, `status`(Uptime
   Kuma), `home`(Home Assistant), 또는 아무 이름과 포트. **로그인 페이지 뒤에** 둘지 물어봐요.
   자체 로그인이 없는 것(n8n, Uptime Kuma)은 yes라고 하세요. 그러면 그것들은
   `https://auth.junsgarden.duckdns.org/auth/`에서 로그인해요.
3. 메뉴가 Caddy 설정과 로그인 페이지 규칙을 쓰고, 확인하고, Caddy를 다시 불러와요.
   무언가 잘못되면 예전 설정으로 되돌려요.
4. 메뉴 `A`(My addresses, 내 주소)가 모든 주소와, 어느 주소에 로그인이 필요한지 보여 줘요.

**안전하게 지키기:**
- 기본은 로그인 페이지 뒤에 두기예요. 자체 로그인이 있는 것(위키, Home Assistant)만 열어 두세요.
- 80과 443 말고는 어떤 포트도 전달하지 마세요. 하위 도메인은 모두 그 두 포트로 들어와요.
- 하위 도메인을 쓰게 되면, 로그인 페이지에 2단계 인증(휴대폰 코드)을 켜는 것이 좋아요(안내서 07, [영어](../07-sso-gate.md)).
- 하위 도메인을 지우면(메뉴 `M`, `13`, 그다음 `3`) 바로 닫혀요.

AI 도우미는 Caddy와 DuckDNS를 잘 알아요: 특별한 것을 하고 싶으면,
`cat /etc/caddy/Caddyfile`(비밀번호가 없어요)의 결과를 질문과 함께 Gemini에 붙여 넣으세요.

## 웹사이트 이름 바꾸기: 다른 웹 이름(선택)

![웹사이트 이름 바꾸기는 먼저 스스로 설명해요](../images/screen-18-website-name.png)

`junsgarden.zapto.org` 말고 다른 이름을 원하나요(예: 어머니 정원을 위한 이름)?
메뉴 `M`, 그다음 `16`(Windows에서는: More, `17`), 또는 `bash garden.sh webname`.
내려받은 바로 뒤, 설치하기 전에도 작동해요.
1. 먼저 '내' No-IP 계정에 새 이름을 추가하세요(A 부분). No-IP 업데이트 프로그램(DUC)은
   내 DDNS 키에 있는 모든 이름을 업데이트하니까 바꿀 필요가 없어요.
2. 새 이름을 입력하세요. `https://`, `http://`, `www.`와 `/` 뒤의 모든 것은 알아서
   빼 줘요. 그래서 `https://www.momsgarden.zapto.org/`는 `momsgarden.zapto.org`가 돼요.
3. 바꿀 파일을 보여 주고(공유 버튼, 개인정보 페이지, 휴대폰 앱의 업데이트 확인
   `site/apps/version.json`, Android 앱의 소스), 각 파일의 사본을
   `logs/web-name-change_날짜/`에 두고, 파일을 바꾸고, 정원이 온라인이면 설정과 정문도
   업데이트하고, 웹사이트를 다시 빌드할지 묻고, 바뀐 내용을 내 git 기록에 저장해요
   (`git show`로 모든 줄을 볼 수 있어요).
4. 이미 앱이 있는 휴대폰은 업데이트를 옛 이름에서 찾아요: 앱을 다시 빌드하고
   (`android-app/README.md`) 휴대폰마다 한 번 설치하세요.

되돌리려면: `logs/web-name-change_날짜/`의 파일을 다시 복사하거나, 옛 이름으로 다시 실행하세요.

> **왜 파일 탐색기가 아니라 메뉴로 하나요?**
> 웹 이름은 파일 12개에 적혀 있어요(목록은 `garden.sh`의 `WEBNAME_FILES`예요: 웹사이트
> 코드, 개인정보 페이지, 휴대폰 앱의 업데이트 파일, Android 앱, `docker-compose.yml` 등).
> 그리고 내 설정(`.env`)과 정문의 설정(Caddy와 로그인 페이지)에도 있어요. 손으로 바꾸면
> 그것을 하나하나 다 찾아야 해요. 하나라도 빠뜨리면 공유 버튼, 휴대폰 앱의 업데이트, 또는
> 정문이 아무 말 없이 옛 이름을 계속 써요. 메뉴는 모두 함께 바꿔요: 새 이름이 웹 이름
> 모양인지 확인하고, 바꾸기 전에 파일 목록을 보여 주고, 파일마다 사본을 두고, `.env`와
> 정문이 옛 이름을 쓰고 있으면 그것도 바꾸고, 웹사이트를 다시 빌드할지 물어요(빌드하면
> 웹사이트가 대답할 때까지 기다려요). 바로 위에 적힌 대로 되돌릴 수 있어요.

## 정원을 인터넷에서 내리기
메뉴 `M`, 그다음 `14`: Caddy를 멈추고, 방화벽에서 포트 80과 443을 닫고, No-IP와 DuckDNS
업데이트 프로그램과 로그인 페이지를 멈춰요. 정원은 집에서 계속 실행돼요. 메뉴 `M`, `1`로
다시 올릴 수 있어요. 공유기의 전달 규칙 두 개도 지우세요.

## 선택: Apache(배우기용)
Apache는 세계의 많은 웹사이트를 돌리고 있어요. `lab/06-install-apache-learn.sh`는
Apache를 `127.0.0.1:8081`에 비공개 연습용 서버로, Caddy 옆에 설치해요.
정문은 계속 Caddy예요. `docker/extras/Caddyfile.with-apache.example`은
Caddy가 `/learn/`을 Apache로 보내는 방법을 보여 줘요. 공유기에서 8081은 전달하지 마세요.

## 인터넷에 올린 뒤 안전 확인
- 점검표(메뉴 `5`): 방화벽에 22(집에서만), 80, 443만 보여야 해요.
- 하루 동안 Caddy를 지켜보세요: `sudo journalctl -u caddy -f`. `/wp-login.php`나
  `/.env`를 찾는 요청은 로봇이고, 404를 받아요. 사이트가 제 일을 하고 있는 거예요.
- 자동 보안 업데이트: `sudo apt install -y unattended-upgrades`, 그다음
  `sudo dpkg-reconfigure -plow unattended-upgrades`를 실행하고 Yes라고 대답하세요.

## 다르게 되면
| 보이는 것 | 할 일 |
|---|---|
| 이름이 집을 가리키지 않아요 | `sudo systemctl status noip-duc`. No-IP 계정에서 호스트 이름이 확인되었나요? 메뉴 `M`, `1`을 다시 실행해서 키를 다시 입력하세요. |
| 집에서는 되는데 밖에서는 안 돼요 | 포트 전달이 잘못됐거나 CGNAT예요(B 부분). 많은 공유기는 안에서 자기 공개 이름을 열지 못해요. 항상 휴대폰 데이터로 테스트하세요. |
| 인증서 오류 | 포트 80과 443이 인터넷에서 정원 컴퓨터까지 닿아야 해요. `sudo journalctl -u caddy -n 50`이 이유를 알려 줘요. 너무 많이 시도했나요? 1시간 기다리고(Let's Encrypt 제한) `.test`로 연습하세요. |
| `/beds`가 계속 로그인 페이지로 보내요 | 비밀번호를 다시 정하세요(메뉴 `U`, `5`). 점검표의 "sign-in page"(로그인 페이지) 줄을 확인하세요. |
| "502 Bad Gateway" | Caddy 뒤의 프로그램이 꺼져 있어요: 메뉴 `2`(시작), 그다음 메뉴 `5`. |
| 한 달 뒤에 이름이 작동하지 않아요 | No-IP의 30일 확인 이메일을 놓쳤어요. No-IP에 로그인해서 확인하세요. |
