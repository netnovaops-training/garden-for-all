# 09. 문제 해결: 무언가 작동하지 않을 때

> 영어 원문: [../09-troubleshooting.md](../09-troubleshooting.md)

## 짧은 버전
*다 읽을 시간이 없나요? 짧은 버전이에요. 전체 안내서는 아래에 있어요.*

- 문제를 고치는 방법이에요: 먼저 순서, 그다음 흔한 문제마다 확인하는 법과 고치는 법.
- 침착하게, 아직 아무것도 바꾸지 마세요. 무엇을 하고 있었는지 적어 두세요.
- 점검표(메뉴 `5`)를 실행하세요. 첫 번째 FAIL 줄을 고치고, 다시 실행하세요.
- 설치가 멈췄다면, 메뉴 `1`을 다시 하면 거기서부터 이어서 해요.
- 하나만 바꾸고, 테스트하고, 무엇을 바꿨는지 적으세요.
- 20분이 지나도 막혀 있나요? 메뉴 `H`가 도움 파일(비밀번호는 들어 있지 않아요)을 만들어요. `backups/`에 백업이 있으니 언제든 되돌릴 수 있어요.
- 배터리가 부풀어 보이거나, 뜨겁거나 타는 냄새가 나거나, 물이 전기 부품에 닿았다면 멈추고 믿는 사람에게 물어보세요.

---

문제는 생기기 마련이에요. 이 페이지는 먼저 **방법**을 알려 주고, 그다음 흔한 문제마다
정확히 무엇을 확인하고 어떻게 고치는지 목록으로 보여 줘요.

## 방법(순서대로 따라 하세요)
1. **침착하세요. 아직 아무것도 바꾸지 마세요.** 무엇을 하고 있었는지, 무엇을
   기대했는지 적어 두세요.
2. **점검표를 실행하세요:** 메뉴 `5`(또는 `bash garden.sh check`). 무엇이 작동하고 무엇이
   작동하지 않는지, 무엇을 하면 되는지 보여 줘요. **첫 번째 FAIL** 줄을 고치고, 다시 실행하세요.
   설치(INSTALL)가 멈췄다면: `logs/install-progress.txt`가 멈춘 단계를 보여 줘요.
   메뉴 `1`을 다시 하면 거기서부터 이어서 해요.
3. **오류를 읽으세요.** 보통 마지막 5줄이 원인을 말해 줘요.
4. **로그를 보세요:**
   - 웹사이트: `docker compose logs --tail 40 site`
   - 데이터베이스: `docker compose logs --tail 40 db`
   - Caddy: `sudo journalctl -u caddy -n 40 --no-pager`
   - No-IP: `sudo journalctl -u noip-duc -n 20 --no-pager`
5. **하나만 바꾸고**, 테스트하고, 무엇을 바꿨는지 적으세요.
6. **20분이 지나도 막혀 있나요?** 메뉴 `H`가 `help/`에 도움 파일을 만들어요
   (비밀번호는 들어 있지 않아요). 읽어 본 다음, Gemini에 붙여 넣거나
   ([16](16-ai-studio.md)을 보세요) 믿는 사람에게 보여 주세요.
7. **막혀서 무언가 망가뜨렸을까 봐 걱정되나요?** 백업이 `backups/`에 있어요.
   언제든 되돌릴 수 있어요.

## 언제든 해 볼 수 있는 빠른 해결
| 해 볼 것 | 명령 |
|---|---|
| 돌아가야 할 모든 것 시작하기 | 메뉴 `2`(또는 `docker compose up -d`) |
| 설치가 중간에 멈췄어요 | 메뉴 `1`을 다시: 끝난 단계를 보여 주고 이어서 해요 |
| 빌드가 몇 분 동안 "멈춘" 것 같아요 | 예전 노트북에서는 Rust 빌드가 느려요. 글자가 가끔이라도 계속 나오면 작동하고 있는 거예요. |
| 설치 바로 뒤에 "Cannot connect to the Docker daemon"(Docker 데몬에 연결할 수 없어요) | 로그아웃했다가 한 번 다시 로그인하세요(docker 그룹 때문이에요). 그때까지는 메뉴가 sudo를 써요. |
| 웹사이트만 다시 시작하기 | `docker compose restart site` |
| 노트북 다시 시작하기(많은 것을 고쳐 줘요) | `sudo reboot` |
| 무엇이 디스크를 쓰고 있는지 보기 | `docker system df`와 `df -h /` |
| 안전하게 공간 비우기 | `bash garden.sh cleanup`(메뉴 `M`, `14`, `5`): 7일이 넘은 정원의 옛 버전만. 먼저 물어봐요. 내 데이터 폴더는 절대 지우지 않아요 |

## Ubuntu와 노트북
| 문제 | 확인 | 해결 |
|---|---|---|
| 노트북이 USB로 시작하지 않아요 | 부팅 메뉴 키(안내서 01, C 부분) | 다른 USB 포트를 써 보세요. USB 메모리를 다시 만드세요(Rufus DD mode). BIOS에서 USB를 맨 앞으로 하세요 |
| 설치 뒤에 화면이 까매요 | 로그인 화면까지 갔나요? | `nomodeset`으로 시작한 다음(안내서 01의 표), 맞는 그래픽 드라이버를 설치하세요 |
| Wi-Fi가 없어요 | `ip a`에 Wi-Fi 줄이 보이나요? | 랜선을 꽂으세요. 메뉴에서 **Additional Drivers**(추가 드라이버)를 찾으세요 |
| 모든 것이 아주 느려요 | `htop`(나가려면 `q`를 누르세요) | 브라우저를 닫으세요. `free -h`로 스왑을 확인하세요. Xubuntu와 SSD를 생각해 보세요 |
| 노트북이 아주 뜨거워요 | 뚜껑이 닫혀 있나요? | 조금 여세요. 받침대 위에 두세요. 통풍구를 청소하세요 |
| 화면이 꺼지거나 노트북이 절전 모드로 들어가요 | `systemctl status sleep.target` | `lab/01-prepare-ubuntu.sh`를 다시 실행하고 다시 시작하세요 |
| `sudo`가 "not in the sudoers file"(sudoers 파일에 없어요)이라고 해요 | 처음 만든 사용자는 허용되어 있어야 해요 | Linux를 아는 믿는 사람에게 물어보세요. 혼자 고치려고 하지 마세요 |

## Docker
| 문제 | 확인 | 해결 |
|---|---|---|
| `permission denied ... docker.sock` | `groups`에 `docker`가 보이나요? | 로그아웃했다가 다시 로그인하세요(또는 다시 시작하세요) |
| `docker: command not found` | `docker --version` | `lab/02-install-docker.sh`를 실행하세요 |
| 빌드가 멈춰요: "killed" 또는 "out of memory"(메모리 부족) | `free -h`, 그다음 `dmesg --level=err` | 스왑을 추가하고(`lab/01-prepare-ubuntu.sh`), 다른 프로그램을 닫고, 다시 빌드하세요 |
| 빌드가 아주 느려요 | 예전 노트북에서는 정상이에요 | 기다리세요. 첫 빌드는 15~45분 걸려요(아주 오래된 노트북이나 Pi에서는 1시간까지) |
| 포트가 이미 쓰이고 있어요 | `sudo ss -ltnp`(:8030을 찾으세요) | 다른 프로그램을 멈추거나, `docker-compose.yml`에서 포트를 바꾸세요 |
| 디스크가 꽉 찼어요 | `df -h /` | `bash garden.sh cleanup`. `backups/`의 예전 파일을 다른 곳에 복사한 뒤 지우세요 |

## 정원 웹사이트
| 문제 | 확인 | 해결 |
|---|---|---|
| `localhost:8030`이 열리지 않아요 | `docker ps`에 `garden-site`가 있나요? | `docker compose up -d`. `docker compose logs site`를 읽어 보세요 |
| healthz에 `{"status":"error"}` | 데이터베이스가 켜져 있나요? `docker compose ps` | `docker compose restart db`, 그다음 `restart site` |
| 로그인할 수 없어요 | 비밀번호를 정했나요? | 메뉴 `U`, 그다음 `5` |
| "Too many tries"(시도가 너무 많아요) | 5번 틀리면 잠겨요 | 15분 기다리세요 |
| 사진이 올라가지 않아요 | `ls -ld local/images` | `chmod -R a+rwX local/images` |
| 비밀번호 이메일이 오지 않아요 | 이메일을 설정했나요? | 메뉴 `8` Settings(설정), `3`, 그리고 테스트 이메일을 보내세요. 스팸함도 확인하세요 |
| 페이지가 비어 있어요 | 아직 식물이 없어요 | `/streamlit/`에서 추가하거나, 백업을 복원하세요 |
| 로그에 `tags_cache.csv`에 대한 갤러리 오류가 있어요 | 갤러리 사진이 있나요? | 사진이 없으면 정상이에요 |
| 다시 시작한 뒤에 사이트가 꺼져 있어요 | `docker ps` | Docker가 알아서 다시 시작해요(그렇게 설정되어 있어요). 메뉴 `3`으로 멈췄다면 멈춘 채로 있어요: 메뉴 `2`로 시작하세요 |

## 인터넷 쪽(Caddy, Apache, No-IP, 공유기)
| 문제 | 확인 | 해결 |
|---|---|---|
| 이름이 주소로 바뀌지 않아요 | `getent hosts junsgarden.zapto.org`(또는 내 웹 이름) | `sudo systemctl status noip-duc`. 키를 확인하세요. noip.com에서 무료 이름을 확인하세요(No-IP가 30일마다 링크를 이메일로 보내요: **Confirm**(확인)을 누르세요) |
| 이름이 엉뚱한 주소를 보여 줘요 | `curl -s https://api.ipify.org`와 비교하세요 | 5~10분 기다리세요. 그 이름의 업데이트 프로그램이 딱 하나만 돌고 있는지 확인하세요 |
| 집에서는 되는데 휴대폰에서는 안 돼요 | Wi-Fi를 끄고 테스트하세요 | 공유기에서 80과 443 포트 전달(안내서 04, D 부분). 어떤 공유기는 안에서 자기 이름에 닿지 못해요. 정상이에요 |
| 자물쇠나 인증서 오류 | `sudo journalctl -u caddy -n 50` | 포트 80과 443이 밖에서 노트북까지 닿아야 해요. 이름이 먼저 주소로 바뀌어야 해요 |
| 502 Bad Gateway | `curl http://127.0.0.1:8030/healthz` | 웹사이트가 꺼져 있어요: `docker compose up -d` |
| Caddy가 시작하지 않아요 | `sudo caddy validate --config /etc/caddy/Caddyfile` | 거기서 알려 주는 줄을 고치세요 |
| Caddy나 Apache에 "Address already in use"(주소가 이미 쓰이고 있어요) | `sudo ss -ltnp`(:80과 :443을 찾으세요) | 80과 443은 Caddy만 쓸 수 있어요. Apache는 127.0.0.1:8081에 있어야 해요(`lab/06-install-apache-learn.sh`) |
| 공유기에 CGNAT나 `100.64.x.x` 주소가 보여요 | 공유기의 WAN 주소를 `ipify`와 비교하세요 | 집에서 사이트를 운영할 수 없어요. 비공개로 접속하려면 Tailscale을 쓰세요 |

### 오래되었거나 맞지 않는 자물쇠 인증서

**보이는 것:** 브라우저가 "Your connection is not private"(연결이 비공개가 아니에요)라고
하거나, 인증서가 만료되었다거나 이 이름에 맞지 않는다고 해요.

**왜:** Caddy(정문)는 약 두 달마다 스스로 새 인증서를 받아요. 그러려면 내 웹 이름이 우리
집을 가리키고, 포트 80과 443이 정원 컴퓨터에 닿아야 해요. 둘 중 하나가 멈추면 예전 인증서가
끝나 버려요.

**이 순서대로 고치세요:**
1. 점검표를 실행하세요: 메뉴 `5`.
2. 웹 이름이 우리 집을 가리키나요? `sudo systemctl status noip-duc`가
   **active (running)**(실행 중)이라고 해야 해요. 아니면: 메뉴 `K`, 그다음 `N`에서 No-IP 키를 다시 붙여 넣으세요.
3. 공유기가 아직 포트 80과 443을 정원 컴퓨터의 주소로 보내고 있나요?
   (안내서 04, D 부분. 주소가 바뀌었다면: 안내서 14.)
4. Caddy에게 이유를 물어보세요: `sudo journalctl -u caddy -n 50`. "error"가 있는 줄을 읽으세요.
5. 정문을 다시 설정하세요: 메뉴 `M`, 그다음 `1`, 그다음 `3`(내 진짜 웹 이름). 설정을 다시
   쓰고, 확인하고, Caddy를 다시 시작해요. 그러면 Caddy가 새 인증서를 받아요(최대 1분).
6. 브라우저에서 **Ctrl+F5**로 페이지를 새로 고치세요.

연습용 이름(`.test`로 끝나는)은 언제나 경고가 나와요. 그건 정상이에요.
Caddy의 안내 페이지: <https://caddyserver.com/docs/automatic-https>.

## Home Assistant, Govee, n8n, ESPHome
| 문제 | 확인 | 해결 |
|---|---|---|
| Home Assistant 페이지가 비어 있어요 | `docker logs --tail 30 homeassistant` | 처음 시작한 뒤 몇 분 기다리세요 |
| Govee 조명을 찾지 못해요 | Govee 앱에서 **LAN Control**(LAN 제어)이 켜져 있나요? 같은 Wi-Fi 네트워크인가요? | 켜세요. 조명과 노트북을 같은 네트워크에 두세요 |
| n8n 이메일 테스트가 실패해요 | 자격 증명(credential) 테스트 메시지 | 앱 비밀번호가 틀렸거나, 2-Step Verification(2단계 인증)이 꺼져 있어요. 포트 587을 써 보세요 |
| 노트북이 ESP32를 못 봐요 | `lsusb` 또는 ESPHome 장치 목록 | 데이터용 USB 케이블을 쓰세요. 연결하는 동안 BOOT를 누르고 있으세요 |
| 센서 값이 이리저리 튀어요 | 헐거운 전선 | 전선을 다시 꽂으세요. GPIO34를 쓰세요 |

## 안전 문제: 멈추고 물어보세요
다음과 같으면 계속하기 전에 멈추고 믿는 사람에게 물어보세요:
- 배터리가 부풀어 보이거나, 무언가에서 뜨겁거나 타는 냄새가 나요.
- 물이 전기 부품에 닿았어요.
- Caddy 로그에 내가 모르는 로그인이나 이상한 요청이 몇 시간 동안 되풀이돼요
  (로봇 몇 개는 정상이에요).
- 실수로 비밀번호를 어딘가에 붙여 넣었어요. 먼저 그 비밀번호를 바꾸고(정원 비밀번호는
  메뉴 `U`, `5`. 키는 메뉴 `K`), 그다음 할 수 있으면 붙여 넣은 것을 지우세요.
